# Отчёт об улучшении 1.3.0

Дата: 25.10.2026. Исходная версия: `care_label_recognition_improved_v3.zip` (v1.2.1).
Все цифры получены скриптами из этого репозитория в этом запуске; таблицы целиком —
`docs/comparison_v1.2.1_vs_v1.3.0.md`, сырые данные — `comparison/`, `docs/eval_1.3.0/`.

## 1. Что было в проекте (исходное состояние)

* Конвейер: проверка качества → поиск контура ярлыка и выравнивание перспективы → бинаризация и
  группировка компонент в кандидаты символов → иерархическая NumPy-CNN (≈0.49 M параметров, вход 64×64,
  68 классов + `not_symbol`) + структурные проверки (крест, точки, черты) + сопоставление с шаблонами →
  подавление дублей, порядок чтения, пороги (0.70 «распознано», 0.30 «неуверенно»).
* Таксономия: 68 классов на основе ISO 3758 / ASTM D5489 / DOCX-таблицы, уже включая `wash_hand_30`,
  варианты P/F/W с одной и двумя чертами и т. п.
* 46 тестов, все проходили. Три фото My Labels v1.2.1 уже распознавала верно (5/5, 4/4, 5/5) —
  ошибки, описанные в задаче, были исправлены в 1.2.0–1.2.1. Поэтому в 1.3.0 My Labels — только
  регрессионный контроль; на них ничего не обучалось и не подбиралось.
* Реальной независимой проверки с разметкой каждого символа в проекте не было (только
  «грубые» метки на уровне фото).

## 2. Данные

Подробно — `docs/datasets.md`, аудит — `docs/vector_datasets_report.json`.

* **Оба приложенных архива `care-label-symbols-main*.zip` — это не фотографии**, а две разные
  библиотеки векторных иконок (MIT): Kobo Labs (31 SVG) и Chen He (43 SVG + те же рисунки в PNG/PDF).
  Разметки рамок и фото в них нет. Использованы как дополнительные *варианты начертания* символов
  для синтетики (с пометкой «синтетика» везде).
* Проверка: 74 SVG открылись, пустых нет; 73 импортированы, 1 исключён (`hechen/iron_no_steam` не
  изображает перечёркнутый пар); 4 файла названы растворителем, а нарисована буква — сопоставлены по
  рисунку (P/F); PNG/PDF-экспорты не использовались как дополнительные образцы (это те же рисунки);
  16 пар разных классов, отличающихся только цифрой/точками/чертой, оставлены раздельными.
* Реальные фото: из открытого репозитория `st-den/thesis-project` взяты только 38 фото частей
  TEST (17) и VALIDATION (21), которые ни одна версия модели не видела при обучении.
  **Я вручную разметил каждый символ каждого фото в порядке чтения** (213 обязательных символов,
  `comparison/thesis_heldout_gt.txt`; нестандартные корейские/японские значки и обрезанные кадром
  помечены как необязательные). Лицензии у репозитория нет → фото только для оценки, в архив не
  включены. Проверка дубликатов (dHash): ближайшее «чужое» фото на расстоянии ≥ 69 бит, с My Labels
  ≥ 92 — пересечений нет.
* Roboflow и Kaggle из этой среды недоступны (сеть отклоняет соединения), поэтому на них в 1.3.0
  **не** обучалось. Знания, полученные прежними версиями на этих наборах, сохранены через тёплый
  старт и дистилляцию (п. 4).

## 3. Изменения в конвейере (не только порог)

| Проблема (найдена на реальных VALIDATION-фото) | Причина | Исправление |
|---|---|---|
| Ряд «слипшихся» значков (крест одного касается соседнего) → 2–3 символа вместо 5 | одна компонента с соотношением сторон > 3 отбрасывалась | очистка от линий таблицы + разрезание по «долинам» профиля (динамическое программирование); широкий бокс удаляется, если части уверенно — символы другой категории; часть никогда не заменяет целый символ |
| Значки в клетках таблицы не находились | рамка таблицы склеивала всё в одну компоненту | удаление длинных горизонтальных/вертикальных линеек, если таблица ≥ ~3 клеток |
| Тканые/выцветшие/светлые на тёмном ярлыки: 0–2 символа | фактура ткани дробит контуры | повторный поиск на сглаженном + CLAHE изображении, только если найдено < 3 уверенных символов; классификатор видит исходные пиксели |
| Ряд обрезан найденным «ярлыком» | ранний выход после поиска внутри контура ярлыка | если уверенные символы касаются края контура, ищем и во всём кадре |
| Символ ряда ошибочно «штрафовался» как буква | соседом считался фрагмент того же символа | перекрывающиеся фрагменты не считаются текстом; добавлен вертикальный текст и штраф одиночным мелким находкам вне ряда |
| Простой шаблон (пустой квадрат с крестом) «вето» на уверенный `dry_tumble_no` | корреляция по внешнему контуру | шаблон-подмножество рисунка класса не может наложить вето |
| Тень/палец внутри кропа → уверенная ошибка (P→A) | карта чернил превращает тень в «сплошную краску» | проверка «сплошной области от края кропа»: −20 % уверенности (на валидации точность таких кропов 50–80 % против 94–97 %) |
| Фото 53 (джинсовая ткань): 120 с на фото | O(N²) группировка компонент | векторизация (≈25 с) |
| Порядок для ярлыка, снятого боком | порядок считался в координатах кадра | порядок в системе координат прочитанного ярлыка (поворот 90/270°) |

## 4. Обучение (что реально сделано)

* **Классификатор (CNN)** — дообучен, веса изменились (sha1 `d70fbfb…` → `31e7111…`).
  Тёплый старт от весов v1.2.1, дистилляция знаний от них же (T = 2, вес 0.7) и L2-якорь к ним
  (0.002) — чтобы не потерять то, чему прежние версии научились на реальных фото Roboflow/GitHub,
  недоступных сейчас. 4 эпохи, Adam, lr 4e-4 с косинусным спадом, повороты ±12°, ~45 мин на 2 vCPU.
  Обучающие данные: 63 336 кропов — повтор исходной синтетики (28 753), иконки из двух архивов
  (5 110), кропы, вырезанные **новым детектором** из 1 800 синтетических фото со сложной компоновкой
  (24 161, включая трудные негативы: текст, логотипы, фактура), шум (2 074), тазики с «30°/30°C/30C»
  (2 600), новые стили руки (480), закрашенный перечёркнутый треугольник (220).
  Аугментации не меняют смысл: перспектива/поворот/сдвиг, толщина линий, разрешение 22–110 px,
  фактура, свет, тень, размытие, шум, JPEG; точки, черты, цифры и кресты не стираются.
  **Выбор эпохи — по 21 реальному фото VALIDATION** (эпоха 3); TEST не использовался до конца.
  Эксперименты, которые не пошли в релиз: прогон без дистилляции (recall на валидации 0.82 —
  хуже старых весов), класс `wash_hand_40` (удалён: модель стала путать его с `wash_30_gentle` на
  реальных фото, реальных примеров нет), усреднение эпох (не лучше эпохи 3).
* **Новый «читатель температуры»** (`temperature.py`, 0.47 M параметров): смотрит на внутреннюю часть
  тазика в 2 раза крупнее и выбирает «нет/30/40/50/60/70/95». Обучен только на синтетике
  (23 720 кропов; 94.1 % на синтетической валидации). Используется только когда основная CNN не
  уверена, какой это тазик, и сам уверен ≥ 0.85; только перераспределяет вероятность между классами
  стирки.
* Таксономия: новых ID нет (совместимость), добавлен вариант `bleach_no` «закрашенный треугольник».
  Новое поле `attributes` у каждого символа: `maxTemperatureC`, `underlines`/`mechanicalAction`,
  `dots`/`maxSoleplateTemperatureC`, `solvent`, `prohibited` и т. д. — смысл не теряется, даже
  если исторический ID неудачен (`pro_dry_p_very_gentle` = P с одной чертой). Также `position`, `row`.

## 7. Известные ограничения и оставшиеся ошибки

* TEST: 15 символов из 90 пропущены (чаще всего первый тазик ряда и перечёркнутый треугольник на
  тканых ярлыках — классификатор «неуверен», а не ошибается), 1 неверный класс (фото 53: утюг с двумя
  точками → три точки, сильная фактура джинсовой ткани). По сравнению с v1.2.1 на TEST добавилась
  эта одна ошибка класса (v1.2.1 на этом фото не нашёл ни одного символа).
* Валидация: фото 22 (ярлык снят боком, длинный текст) — 2 лишних `iron_no` в тексте; 36 —
  `wash_hand` прочитан как `wash_hand_30`.
* Синтетика: ряд из 7 символов — полная последовательность 70 → 50 % (новая частая путаница
  wash_60 ↔ wash_95/wash_50 на мелких цифрах: ряд из 7 мельче); сильная перспектива 87.5 → 84.0 %;
  логотипы — ложных срабатываний больше (0.30 → 0.40 на фото); «слипшиеся» символы находятся вдвое
  чаще, но и неверных классов там больше (5 → 10 на 149). Это зафиксировано, не скрыто.
* Только 38 реальных фото с полной разметкой — погрешность метрик большая (±5–7 п. п.).
  Нужна собственная выборка фото из приложения.
* Иконки двух архивов — те же «рисунки», на которых модель обучалась; наборы D13/D14 проверяют
  устойчивость к искажениям, а не обобщение на новый дизайн.
* Мелкие символы (< ~30 px) по-прежнему плохо (синтетика: 55 % верно).
* Время: 1–4 с на фото, до ~25 с на крупных фото с сильной фактурой (повторный поиск).

```bash
pip install -r requirements.txt
python run_folder.py ПАПКА_С_ФОТО                 # аннотированные фото + JSON + summary.csv
python recognize.py фото.jpg                      # JSON в консоль

# повторное обучение и оценка — README.md, раздел «1.3.0: training, evaluation, inference»
```

Примечание о воспроизводимости: в выпущенных весах набор `newcls_train` содержал только закрашенный
вариант `bleach_no` (220 кропов, сгенерирован вручную тем же рендерером); `training/run_v4_data.sh`
теперь строит этот набор из всех вариантов `bleach_no` — итог обучения может немного отличаться.
